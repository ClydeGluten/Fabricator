# Синхронизация модов с инстанциями Modrinth

В разделе **Mods → Modrinth instance sync** выберите инстанцию и нажмите
**Preview sync**. Панель покажет добавления, замены, удаления и клиентские моды,
которые она пропустит. После остановки **игрового сервера** нажмите **Apply sync**.
Далее запускайте игровой сервер обычной кнопкой Start. После первоначальной
настройки перезапуск контейнера для каждой синхронизации не нужен.

Это синхронизация **инстанция → сервер**, запускаемая кнопкой. Изменения сервера
не записываются обратно в Modrinth. Копируются точные локальные `.jar`, а не
новейшие версии из каталога. Миры, конфиги, ресурспаки и шейдеры не копируются.
Идентификация модов использует публичный API Modrinth по хешам файлов; учётная
запись и токен Modrinth не нужны. Стоимость дополнительных сервисов — $0/месяц.

## Подключение папки один раз

Для Linux с установленным Modrinth App:

```bash
cd ~/Documents/Soft/Fabricator-fork
python3 tools/setup-modrinth.py "$HOME/.local/share/ModrinthApp/profiles"
```

Скрипт создаёт приватный локальный `.env.modrinth` и **не перезапускает контейнер**.
Когда готовы к обновлению, сохраните мир и остановите игровой сервер через Stop
в панели. Затем:

```bash
./tools/home-compose.sh up -d --build
```

Нужен именно `up`, а не `docker restart`: Docker должен пересоздать контейнер
с новой папкой, подключённой **только для чтения**. Файлы сервера остаются в вашем
прежнем `/data`. Панель и игровой порт сохраняются из `.env.home`.

Подключается только каталог `profiles`. База `app.db`, аккаунты, сессии Modrinth
и папки других приложений в контейнер не передаются.

Если Modrinth хранит инстанции в другом месте, укажите путь к папке, **внутри
которой лежат каталоги инстанций**. Для замены уже подключённого корня:

```bash
python3 tools/setup-modrinth.py --replace /путь/к/profiles
./tools/home-compose.sh up -d --build
```

Для установки без Docker задайте переменную `FABRICATOR_MODRINTH_PROFILES`
с путём к такому каталогу перед запуском панели.

## Новые инстанции и несколько серверов

1. Создайте или импортируйте инстанцию в Modrinth и установите в неё моды.
2. В панели нужного сервера откройте Mods и нажмите **Refresh list**.
3. Выберите новую инстанцию, затем **Preview sync → Apply sync**.

Новые папки внутри подключённого корня обнаруживаются без пересоздания контейнера.
У каждого сервера своя сохранённая инстанция. Сменить её можно тем же списком.
При переключении источника предварительный просмотр также покажет удаление
модов, которыми управляла предыдущая синхронизация.

Инстанция на другом компьютере должна быть сначала скопирована в подключённую
папку. Вход в аккаунт Modrinth сам по себе не даёт панели доступ к файлам другого ПК.

## Что считается клиентским

- Явный `environment: client` внутри Fabric/Quilt jar исключает этот файл.
- Modrinth `client_only`, `singleplayer_only` либо старое
  `server_side=unsupported` также исключают файл.
- **Необязательные на сервере моды сохраняются**, в том числе
  `client_only_server_optional` и `server_side=optional`.
- Если совместимость неизвестна, мод **не исключается**: он попадёт в отдельный
  список Unknown и будет включён в синхронизацию. Проверьте этот список перед
  запуском. Ошибочные или отсутствующие метаданные авторов нельзя гарантированно
  исправить автоматически.
- Наличие клиентских классов или только клиентской точки входа само по себе
  не является основанием исключать универсальный мод или библиотеку.
- Отключённые в Modrinth файлы `.jar.disabled` не устанавливаются.

При недоступности API панель явно предупреждает об этом, продолжая учитывать
метаданные внутри jar. Имена файлов и названия проектов не используются для
угадывания стороны. Данные API о версиях Minecraft дают предупреждения; несовпадение
загрузчика или несколько активных файлов одного мода блокируют применение.

## Замены, удаления и конфликты

При смене имени jar старая версия определяется по Modrinth project ID или ID
мода из манифеста. Старая версия заменяется без оставления второй копии.

Отсутствующий в инстанции мод удаляется **только если он участвовал в предыдущей
синхронизации**. Самостоятельно добавленные серверные моды сохраняются. Отмеченные
как синхронизированные файлы закрепляются: Update all не обновит их отдельно
от инстанции. Чтобы обновить сборку, обновите Modrinth и снова выполните синхронизацию.

Если управляемый файл изменён вручную на сервере, панель покажет конфликт.
При остановленном сервере сохраните свою копию и удалите конфликтующий jar
либо восстановите его прежнюю версию, затем повторите Preview. При двух активных
версиях одного мода в инстанции оставьте там одну нужную версию.

Предпросмотр действует 15 минут. Если после него изменились моды или настройки
сервера, понадобится новый Preview. Применение на работающем сервере запрещено
и в интерфейсе, и на стороне API.

## Резервная копия и восстановление

До замены сохраняется прежняя папка `mods` целиком:

```text
servers/<id>/mod-sync-backups/<дата-и-id>/
  mods/          прежние моды, включая серверные дополнения
  before.json    прежние записи Modrinth и состояние синхронизации
```

Путь к копии показан после Apply. Копии автоматически не удаляются: после проверки
сборки ненужные старые копии можно удалить через файловый менеджер.

При обычной ошибке записи исходная папка автоматически возвращается. Если процесс
был аварийно прерван посреди замены, остаётся файл `.modrinth-sync-in-progress.json`;
до восстановления запуск игрового сервера блокируется, чтобы он не открыл мир
с неполным набором модов.

Для ручного отката остановите панель через `./tools/home-compose.sh stop`, сохраните
текущую папку `servers/<id>/mods` под другим именем и скопируйте `mods` из нужной
резервной копии на её место. В `servers.json` для этого сервера восстановите
`modContent` из `before.json → previousModContent` и `modrinthSync` из
`before.json → previousSync`. При восстановлении после прерывания ID копии записан
в `.modrinth-sync-in-progress.json`; если в ней ещё нет папки `mods`, старую папку
ещё не успели переместить и её нужно оставить. После восстановления удалите маркер
и запустите панель через `./tools/home-compose.sh up -d`.

## Проверки реализации

Тесты покрывают классификацию, сервер-необязательные моды, новые инстанции,
смену источника, замены версий, удаление только управляемых файлов, сохранение
серверных дополнений, защиту путей, устаревшие планы, откат после ошибки и запрет
применения на работающем сервере. Браузерные проверки используют временные данные.

Источники контрактов: [Modrinth API](https://docs.modrinth.com/api/),
[метаданные проекта](https://docs.modrinth.com/api/operations/getproject/),
[формат Fabric manifest](https://wiki.fabricmc.net/documentation:fabric_mod_json_spec).

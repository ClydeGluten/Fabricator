# Домашний форк Fabricator: запуск, перенос и DuckDNS

Форк: https://github.com/ClydeGluten/Fabricator. Владелец: ClydeGluten.
Исходный проект: https://github.com/philderks/Fabricator, лицензия AGPL-3.0.

## Что добавлено

- Все постоянные данные контейнера лежат в выбранной обычной папке хоста.
  Процесс работает с UID/GID владельца папки: файлы можно добавлять и удалять
  через Dolphin, без `docker exec` и без `sudo`.
- Нажатие на имя игрока открывает координаты, измерение, здоровье, голод,
  уровень опыта, игровой режим, инвентарь, броню и эндер-сундук. Предметы из
  модов показываются с их ID и количеством; компоненты/NBT можно раскрыть.
- Для онлайн-игроков: вылечить, накормить, убрать эффекты, сменить режим,
  телепортировать по координатам и измерению или к другому онлайн-игроку.
  Кик, бан и права оператора остаются в списке игроков.
- Отдельный вайтлист: поиск, добавление до 20 имён за раз, импорт имён из TXT
  или `whitelist.json`, экспорт, удаление с отменой и постоянный выключатель.

Инвентарь доступен для просмотра. Файлы данных игрока панель не изменяет.
`Live read` означает ответ сервера на запрос при открытии карточки/обновлении;
нажмите Refresh для следующего чтения. `Last saved data` — состояние на момент
указанного сохранения, которое может отставать от игры. Если сервер не отвечает
на стандартную команду `data get entity`, будет показано сохранение с предупреждением.
Для этих функций RCON и дополнительный серверный мод не нужны.

## Чистый запуск рядом с существующей панелью

Нужны Linux, Docker с Compose и Python 3. Запускайте команды обычным пользователем,
которому доступен Docker. Стоимость сервисов: $0/месяц; используются ваш ПК и интернет.

```bash
git clone https://github.com/ClydeGluten/Fabricator.git Fabricator-fork
cd Fabricator-fork
python3 tools/setup-home.py "$HOME/Games/Fabricator-fork-data"
./tools/home-compose.sh up -d --build
```

Откройте **http://127.0.0.1:5001** и создайте пароль новой панели. Подключение к
тестовому Minecraft: **127.0.0.1:25566**; внутри панели серверу оставьте порт 25565.
Эти адреса доступны только с этого компьютера, пока вы не измените привязку.

Используется отдельный Compose-проект `fabricator-home`, отдельный образ
`fabricator-home:local` и файл `.env.home`. Исходный контейнер `fabricator` и его
именованный volume не подключаются к новому проекту. Самостоятельное обновление
из upstream отключено: обновляйте этот форк через Git и пересборку.

Для выбора другой папки передайте её `setup-home.py`. Скрипт не заменяет
существующий `.env.home`; менять готовую конфигурацию можно текстовым редактором.
Папку с данными лучше держать вне Git-репозитория. Она содержит миры и секреты панели.

## Где находятся файлы

```text
~/Games/Fabricator-fork-data/
  servers.json                 список серверов и их настройки
  servers/<id>/mods/           моды конкретного сервера
  servers/<id>/plugins/        плагины, если используется Paper/Purpur
  servers/<id>/server.properties
  servers/<id>/whitelist.json
  servers/<id>/<имя мира>/     мир (имя задано в level-name)
  backups/                    резервные копии
  java/                       Java, установленная панелью
```

Перед заменой модов, конфигурации или мира остановите **этот игровой сервер**
в панели, внесите изменения в папку и запустите его. Изменения работающего мира
могут быть перезаписаны игрой. Вайтлист удобнее редактировать в панели: она
перезагружает список на работающем сервере.

## Перенос со старого контейнера — когда будете готовы

Этот раздел выполняется вручную в выбранный момент. В рамках разработки форка
рабочий контейнер не останавливался и данные не переносились.

1. Остановите только новый предварительный экземпляр и отложите его данные.
   Убедитесь, что в этой предварительной папке нет нужного нового игрового мира.

   ```bash
   cd ~/Documents/Soft/Fabricator-fork
   ./tools/home-compose.sh down
   mv "$HOME/Games/Fabricator-fork-data" "$HOME/Games/Fabricator-fork-preview-$(date +%Y%m%d-%H%M%S)"
   mkdir -m 700 "$HOME/Games/Fabricator-fork-data"
   ```

2. Остановите рабочий контейнер с сохранением мира и скопируйте **весь `/data`**.
   Нельзя снимать такую файловую копию во время записи игрового мира.

   ```bash
   docker stop --time 60 fabricator
   docker cp fabricator:/data/. "$HOME/Games/Fabricator-fork-data/"
   ```

   Выполняйте `docker cp` без `sudo` и без `-a`: файлы на хосте должны принадлежать
   вашему пользователю. Старый контейнер и его volume сохраняются для отката.
   Полная копия переносит также настройки, Java, пароль панели и резервные копии.
   Внутренний путь остаётся `/data`, поэтому существующие пути серверов сохраняются.

3. В `.env.home` выставьте рабочие порты:

   ```dotenv
   FABRICATOR_PANEL_PORT='5000'
   FABRICATOR_GAME_PORT='25565'
   FABRICATOR_GAME_BIND='0.0.0.0'
   ```

   Остальные строки — выбранная папка и UID/GID — оставьте как создал скрипт.
   Порт 5000 панели по-прежнему публикуется только на `127.0.0.1`.

4. Запустите форк и проверьте сервер:

   ```bash
   ./tools/home-compose.sh up -d --build
   ./tools/home-compose.sh logs --tail=80
   ```

   Панель теперь на http://127.0.0.1:5000. Серверы с включённым автозапуском
   запустятся из скопированных настроек. Существующее перенаправление Tailscale
   на localhost:5000 продолжит вести к панели. Домен и правило роутера не меняются,
   если хост и внешний игровой порт прежние.

Для отката: `./tools/home-compose.sh down`, затем `docker start fabricator`.
Старый мир останется в состоянии на момент копирования: игровой прогресс,
полученный в форке после переноса, автоматически назад не попадёт.
Не удаляйте старый volume, пока не проверили перенос.

## Вайтлист

В разделе Players вставьте имена друзей в поле Add players и нажмите Add to
whitelist. Для online-mode нужны существующие Minecraft Java аккаунты; ошибки
поиска показываются для каждого имени. Для offline-mode UUID рассчитываются
локально, регистр имени важен при первом добавлении.

Выключатель **Only whitelisted players can join** управляет `white-list`, работает
при включённом и выключенном сервере и сохраняется после перезапуска. Операторы
Minecraft могут обходить вайтлист. Отдельная настройка **Kick players removed from
the whitelist** соответствует `enforce-whitelist`: она определяет отключение
удалённых из списка игроков после его перезагрузки, а не включение самого списка.

## Белый IP, роутер и DuckDNS

DuckDNS связывает имя с IP-адресом. Входящие пакеты до Minecraft доставляют
маршрутизатор, проброс порта и Docker; DNS их не туннелирует и не обходит CGNAT.
Динамического публичного IPv4 достаточно, постоянный статический IP не обязателен.

### 1. Закрепите локальный адрес ПК

```bash
ip -brief address
ip route show default
curl -4 -fsS https://api.ipify.org
```

В роутере закрепите LAN-адрес ПК за его MAC через DHCP reservation. Для вашей
существующей установки использовался `192.168.1.234`; при смене сети проверьте его
заново. Сверьте WAN IPv4 роутера с внешним адресом. WAN из `100.64.0.0/10`, `10/8`,
`172.16/12`, `192.168/16` требует проверки дополнительного NAT у провайдера/модема.

### 2. Пробросьте игровой порт

В Port forwarding/NAT роутера: внешний **TCP 25565 → LAN-адрес ПК:25565**.
В Docker нужен `FABRICATOR_GAME_BIND='0.0.0.0'` и `FABRICATOR_GAME_PORT='25565'`.
Если используете UFW, разрешите входящий игровой порт:

```bash
sudo ufw allow 25565/tcp comment 'Minecraft Java'
```

Minecraft Java для обычной игры использует TCP. UDP открывайте для конкретной
функции, которой он нужен. Например, Simple Voice Chat часто использует UDP 24454:
нужны отдельные правила роутера, Docker и фаервола на порт из конфигурации мода.
Панель 5000 и RCON для друзей открывать не требуется.

### 3. Зарегистрируйте имя в DuckDNS

На https://www.duckdns.org войдите в свой аккаунт, добавьте свободный поддомен
и сохраните токен. Для уже настроенного поддомена повторная регистрация не нужна. Не публикуйте токен, файл конфигурации или `/data` в GitHub.

На этой машине обновляющий скрипт уже установлен отдельно от Fabricator:

```bash
systemctl --user status minecraft-ddns.timer
systemctl --user start minecraft-ddns.service
journalctl --user -u minecraft-ddns.service -n 10 --no-pager
```

Его конфигурация — `~/.config/minecraft-ddns/config.json`: `domain` без суффикса
`.duckdns.org`, `token`, `interface` физической сети (например, `enp6s0`). Токен
не нужно переносить в контейнер. Таймер обновляет запись каждые пять минут.

Для **другого компьютера**, где такого обновления ещё нет:

```bash
install -d -m 700 ~/.config/minecraft-ddns
install -d ~/.local/bin ~/.config/systemd/user
install -m 755 tools/duckdns/update.py ~/.local/bin/update-minecraft-ddns
install -m 644 tools/duckdns/minecraft-ddns.service tools/duckdns/minecraft-ddns.timer ~/.config/systemd/user/
python3 tools/duckdns/configure.py
systemctl --user daemon-reload
systemctl --user enable --now minecraft-ddns.timer
systemctl --user start minecraft-ddns.service
sudo loginctl enable-linger "$USER"
```

Скрипт конфигурации спросит имя, интерфейс и токен без отображения токена.
Не перезаписывает готовую конфигурацию. Обновление идёт через указанный физический
интерфейс, чтобы не публиковать выходной IP VPN. Если VPN запрещает этот выход,
обновление завершится ошибкой; настройте исключение для него или отключите VPN.

### 4. Проверьте из другой сети

Запустите игровой сервер и попросите друга подключиться к `ваше-имя.duckdns.org`.
При стандартном порте `:25565` можно не писать. В Windows доступность TCP проверяется:

```powershell
Test-NetConnection ваше-имя.duckdns.org -Port 25565
```

У себя на серверном ПК используйте `localhost:25565`; на другом домашнем ПК —
LAN-адрес сервера. Если роутер не поддерживает NAT loopback, доменное имя из той же
домашней сети может не работать, хотя друзья из интернета подключаются.

Официальные справочники: [Docker bind mounts](https://docs.docker.com/engine/storage/bind-mounts/),
[DuckDNS API](https://www.duckdns.org/spec.jsp), [назначение DDNS](https://www.duckdns.org/why.jsp).

## Разработка и проверка изменений

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m pytest -q
cd frontend
npm ci
npm test
npm run build
npx playwright install chromium
npm run test:browser
```

Браузерные тесты поднимают временную панель на 127.0.0.1:5057 с отдельными
синтетическими данными. Они не подключаются к рабочему контейнеру или его миру.
CI выполняет эти проверки и сборку Docker перед слиянием изменений.
